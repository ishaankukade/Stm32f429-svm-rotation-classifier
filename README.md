# Rotation Direction Classifier: Linear SVM on STM32F429I-DISC1

An on-device machine-learning project for the **STM32F429I-DISC1** board. Using the on-board **L3GD20 gyroscope**, it trains a **linear SVM** directly on the microcontroller to recognise whether the board is rotating **clockwise (CW)**, **counter-clockwise (CCW)** or sitting **STILL**, then classifies motion live over UART.

## Features
- Data collection, training and inference all run **on the board**, with no PC-side ML tooling
- **One-vs-rest linear SVM**: 3 classifiers, `score_k = w_k · x + b_k`, prediction = `argmax`
- Trained with **hinge-loss SGD**, L2 regularisation, learning-rate decay and shuffled samples
- **Feature standardisation** (zero mean, unit variance) computed from the training set
- Free-style **live classification** after training, with raw features and scores printed
- Optional fixed 15-sample test with accuracy and a **confusion matrix**
- Integer-only accuracy printing, so float `printf` support is not needed

## Classes
| Label | Class | Meaning |
|---|---|---|
| 0 | CW | Clockwise rotation |
| 1 | CCW | Counter-clockwise rotation |
| 2 | STILL | No rotation |

## Features Used
Each sample averages 10 gyro readings (about 10 ms apart):

| Index | Feature |
|---|---|
| 0 | X mean rate (signed, carries the direction) |
| 1 | Y mean rate |
| 2 | Z mean rate |
| 3 | Magnitude √(x² + y² + z²) |

## Hardware
- **STM32F429I-DISC1** (on-board L3GD20 gyroscope on SPI5, chip select on PC1)
- USB cable (ST-LINK) for programming
- **USART1 at 9600 baud, 8N1** for the serial output. Connect a USB-UART adapter to the USART1 pins, or route USART1 through the ST-LINK virtual COM port if your board setup allows it.

## How to Rotate the Board
Rotate about the **X axis like the spindle of a wall clock**: the X axis points out of the wall toward you and the board turns like clock hands (not flat like a turntable). Always view the board from the **same side** when deciding what is CW and CCW. The SVM learns whatever you demonstrate, so just stay consistent between training and testing.

## Usage
1. Create/import an **STM32CubeIDE** project for the STM32F429I-DISC1 with HAL drivers (see *Project Setup*).
2. Build and flash.
3. Open a serial terminal at **9600 baud**.
4. Follow the prompts. Each phase starts after a 5-second countdown:
   - **Step 1:** collect 50 CW, 50 CCW and 50 STILL samples
   - **Step 2:** initialise the SVM and compute normalisation
   - **Step 3:** train the three classifiers
   - **Live mode:** rotate CW, CCW or stay still in any order and watch the predictions

Example live output:
```
LIVE: X=..., Y=..., Z=..., Mag=... | score CW=.. CCW=.. STILL=.. (x100) -> CW
```

## Configuration
Edit the settings at the top of `Core/Src/main.c`:
```c
#define TRAIN_PER_CLASS      50     // training samples per class
#define TEST_PER_CLASS       5      // samples per class in the fixed test
#define READINGS_PER_SAMPLE  10     // gyro readings averaged per sample
#define ENABLE_FIXED_TEST    0      // 1 = run fixed 15-sample test before live mode

#define SVM_EPOCHS           300
#define SVM_LEARNING_RATE    0.01f
#define SVM_LAMBDA           0.001f // L2 regularisation
#define SVM_POS_WEIGHT       2.0f   // balances one-vs-rest data
```

## Project Setup
`main.c` includes `main.h` and uses the HAL, which are generated by STM32CubeMX/CubeIDE, so the generated project files are not included in this repository. To use it:
1. In STM32CubeIDE create a new project for board **STM32F429I-DISC1** with HAL.
2. Replace the generated `Core/Src/main.c` with the one in this repo.
3. Make sure the math library is linked (`sqrtf`).

## Known Limitations
- Training data is lost on reset, so the board retrains from scratch at every power-up.
- The shuffling RNG uses a fixed seed, so training is repeatable but not varied.
- Gyro bias (zero-rate offset) is not calibrated, which may affect the STILL class between sessions.
- Each axis register pair is read in two separate SPI transactions, so low and high bytes are not guaranteed to come from the same sample.
- Only rotation about the X axis is considered by design, and a linear model cannot capture complex motions.
- Pins PA1 and PA2 are initialised as inputs but never used.

## Possible Improvements
- Remove gyro offset by averaging readings while stationary at start-up
- Read all six axis registers in one multi-byte SPI burst (auto-increment)
- Store trained weights in flash so training is not repeated
- Show the result on the on-board LCD or LEDs
- Add more motion classes or time-window features
